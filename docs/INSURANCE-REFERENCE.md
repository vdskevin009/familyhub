# Private insurance reference — FH-SAV-012 / #241

Insurance remains part of existing shared Savings contracts. Optional `insuranceReference` contains schema 1, UTC `updatedAt`, referenced evidence sources, and separately identified records for policies, building/strata certificates, memberships, quote requests and received quotes. There is no second household store, scheduler, provider integration or automatic contract change.

Records retain effective/request/receipt/validity dates, optional quoted annual premium in CAD, assumptions, differences, comparison state, limitations and typed facts. Each fact has a stable dotted code, label, scalar/null value, unit, certainty and source IDs. Unknown certainty requires null, never artificial zero. Personal deductibles, building deductibles and personal-policy reimbursement sub-limits are separate. A broad aggregate limit cannot establish an unknown sub-limit. Historical membership is not current membership proof; observed monthly debits do not prove current annual fee, people or tier. Financing, registration, Basic and Optional premiums are separately labeled and never summed twice.

Provenance distinguishes original documents, partial captures, historical evidence, payments, statements, quotes and advertising, plus locally-read/reported-verified/unverified evidence. A reference ID does not claim attached/materialized bytes. Source date may be unknown. Never invent local paths for cloud files. Quote requests can be preparing, sent or awaiting_quote, with no received date, quoted premium or validity. Received quotes require a dated non-public quote source; advertising cannot become a quote. Reviewed comparability requires known price/validity and no unresolved facts/differences. The reference never solicits or buys insurance.

## Existing private API

Use existing pairing/origin controls. GET `/health` must announce `insurance-reference-v1` before new metadata writes; no credential/scope is added. GET `/savings/contracts` returns `{records:[{contract,revision}]}` including the reference. POST `/savings/contracts/:id` accepts `{contract,expectedRevision,documents:[]}`. Existing attached document bytes remain available; supply new bytes only for actual new attachments. Canonically identical updates are no-ops; stale revisions return409. Read after writing, and read first after uncertain outcomes.

Sources/records are immutable by ID. Corrections append an identified record with optional `supersedes`, preserving history. Older editors omitting the reference cannot erase it. Existing edits/backups retain the optional field. Non-insurance contract signatures remain compatible. Private reference edits invalidate the local research fingerprint, while `publicBaseline` and outgoing research prompts omit the reference. Policy names, personal facts and evidence IDs never enter public searches.

Details expose records, unknowns and provenance plus a private JSON download: `{schema:1,kind:"private-insurance-reference",exportedAt,contractId,category,reference}`. It contains private evidence, stays local and is not automatically uploaded. Assistants can reuse this export or the authenticated existing GET. It contains no secrets or unrelated household state. Synthetic tests are separate from deployment, physical-phone checks and actual policy completeness/eligibility.
