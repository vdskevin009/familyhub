# FamilyHub design review: first wave

Requirement FH-UX-004. Baseline: `bc4630215c3fbb3fa6cebbd2b61f8984f9097d3b`, which already includes the confirmed-only contribution rings. The review covers the existing five destinations, deep links, and associated public PWA views. Source review is broader than the implemented first wave. Synthetic captures are not evidence of live data, source coverage, notification receipt, or financial outcomes.

## Direction: a household field notebook

Use the existing Pacific-blue action accent, neutral canvas and easy-to-read system type, so the app remains recognisable in both themes. One softly tinted lead action on Today, a plain list of other decisions, and a quieter money snapshot. Preserve the signs, dates and caveats that change the decision. Keep source and history behind one useful action; don't fill unused space with gamification or decorative chart data.

| Area | Evidence from the existing app | Decision |
| --- | --- | --- |
| Today and navigation | Money tiles interrupted the list after the first action; each repeated action had the lead card's visual weight. The active dock selection switched as independent tiles. | **Delivered in this wave:** lead with an editorial date and first action, group supporting rows, keep all three qualified amounts together after actions. One moving active treatment tracks touch/pointer navigation; the page itself does not animate. |
| Contributions | At 390 px, the Finances ledger refresh and the Contributions refresh competed. Confirmed example showed a ring; a current-worker-shaped partial example correctly did not. | **Delivered in this wave:** use one context-specific refresh, keep confirmed rings, streamline amount typography and snap/animate only per existing confirmed-change semantics. No guessed percentages or new source policy. |
| Important Mail, Notifications | Important Mail can show six of seven items with no continuation; its lower Important tab may instead filter documents and render none. Notification rows lead with generic category guidance while the item-specific reason is closed in Sources. | **Next: high priority.** Give Important Mail one real list and transparent pagination; place the actual event's reason and next step first. Keep source and private details behind the existing authenticated views, never in lock-screen text. |
| Claims, Documents, insurer sources | At 390 px in a fictional claim, the first card started about 579 px down, after repeated totals/source controls; the first decision fell below the visible area. Documents has source tabs plus an Invoices/Excluded classification row. Refresh on insurer libraries reads existing results, not new statements. | **Next: high priority.** Get to one claim action before secondary controls; use one Documents source switch and a secondary Excluded treatment. Label saved-result reads accurately and link existing collection/reconnect rather than creating a new workflow. |
| Accounts, Spending, Trends, Mortgage, Recurring and Money | A fictional empty Money workspace shows `$0.00 Imported this month` over `No spending imported`. Accounts buries coverage and version selection. Spending and Recurring serve different jobs but overlap visibly. Mortgage/Recurring keep important current-versus-history qualifiers behind detail. | **Next: high priority for unknown-as-zero.** Make missing distinct from zero; show reference/evidence date by the relevant figure; label actual spending vs recurring contract review and keep evidence in its own currency/source. Do not change reported figures as part of visual work. |
| Projects, property and vehicles | Project entry and listing cards are clear enough to navigate, but property criteria text and generic price-at-review are rendered regardless of per-item evidence. The amount of copy crowds the image and decision. | Show the image, price and one supportable assessment first. Keep comparable sales/condition/source checks in a deliberate second layer. Absence and staleness remain explicit; apply the same card structure to vehicles without inventing a rating. |
| Groceries, Planner, More, Settings | Purchases presents a one-button tab; it and Planner's grocery list have similar names for different modes. Planner has unnamed controls and repeated planning actions. Settings includes appearance, installation, connections, watch setup and restore in one long flow. | Separate Shopping list from Purchase history, offer a direct handoff and one named add action. Give Planner controls accessible names and safer delete handling. Group quick preferences, connection status and advanced tools without hiding installation or restore safety. |

Individual workflow recommendations beyond Today/nav/Contributions are proposals only. Audit intentionally does not enter real files, accounts or external portals.

## Motion review

References read, not installed or executed: [Impeccable by Design](https://www.paulbakaus.com/impeccable-by-design/) for removing repeated visual hierarchy, [Emil Kowalski's Apple Design guidance](https://github.com/emilkowalski/skills/blob/main/skills/apple-design/SKILL.md) for spatial continuity, and [Review Animations](https://github.com/emilkowalski/skills/blob/main/skills/review-animations/SKILL.md) for restrained timing, reduced motion and interactivity. No Spline: a 3D scene has no role in deciding the household's next action.

| Before | After | Why |
| --- | --- | --- |
| Active fill per dock tile and a separate top bar | One interruptible 220 ms transform for explicit pointer movement; keyboard, Back and direct entry are instant | Shows where navigation moved without moving the screen or delaying the next action |
| Shared sheets played the same 160 ms entrance for keyboard and pointer | 235 ms pointer entrance with 8 px desktop / 18 px mobile travel; keyboard and reduced motion open and close without movement | A small rise shows the sheet's relationship to the page; native dialog semantics, Escape and focus return remain in control |
| Contributions used the existing 320 ms arc adjustment | 260 ms arc adjustment only when verified values change against the same goal; no initial, unknown, repeated or reduced-motion animation | Preserves the explanatory graph while shortening a small, finite SVG paint. Never use this treatment as simulated loading |
| Decorative skeleton shimmer during source loading | Static placeholders on Today with the same status name | Avoid an ambient loop in the screen used most often |

The only continuous animated element added is none. Short press/chevron feedback uses transform only. No external assets or runtime dependencies are added, and broad accessibility or real-device performance conformance is not claimed.
